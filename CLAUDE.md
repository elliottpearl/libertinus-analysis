# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A diagnostic sandbox for combining-mark (GPOS mark-to-base) behavior in Libertinus Serif, aimed at IPA and linguistics notation. It measures the four original fonts, reports on them in a XeLaTeX PDF, and builds patched fonts (`fonts/*-patch.otf`) with corrected and added anchors. It is exploratory and unfinished; expect legacy modules and half-built stages.

## Commands

There is no test suite and no linter. Work is driven by top-level `run_*` wrapper scripts, which are edited in place to choose inputs and then executed. **Always run them from the repo root**: several modules use paths relative to the working directory (`data/fea/...`, `data/fontmetrics/...`, `data/fontanchors_implied/...`), and `data/` is imported as a top-level package from the root.

```bash
# normal environment (everything except FontForge scripts)
.venv/bin/python run_print_report_fontmetrics_full.py # fontmetrics -> tex/input/fontmetrics_*.tex
.venv/bin/python run_anchor_copy_report.py            # clusters of identical anchors -> tex/input/copied_anchors.tex
.venv/bin/python run_anchor_audit.py                  # bad/suspect designer anchors -> data/fontanchors_audit/{style}.py
.venv/bin/python run_print_combo_matrix.py            # base x mark grids, original vs patched fonts
.venv/bin/python run_patch_font.py                    # fonts/*.otf -> fonts/*-patch.otf, then writes the mark zone figures
.venv/bin/python run_print_mark_zones.py              # patched fonts -> tex/input/mark_zones_{style}.tex, figures of all marks on o (run_patch_font.py does this too)
.venv/bin/python run_mark_snap_sheet.py               # patched fonts -> fonts/*-marksnap.otf (mark anchor X moved to C + Y tan θ + d − K) and tex/input/mark_snap.tex, a test sheet (not \input by the report since 2026-11-06; the snap was rejected as a stage, see the report)
./run_xelatex_report.sh                               # tex/libertinus-analysis.tex -> PDF
.venv/bin/python run_precomposed_existing_report.py    # after run_patch_font.py: precomposed letters that keep a designer/curated anchor vs what stage 9 would inherit -> tex/input/precomposed_existing.tex (a check; not \input by the report since 2026-11-10)
.venv/bin/python run_print_lane_comparison.py         # italic base-anchor candidate X, advance lane vs ink lane -> tex/input/lane_comparison_*.tex; PDF: cd tex && xelatex lane-comparison.tex (separate from the report)
.venv/bin/python run_build_fontmetrics.py             # optional: dump metrics to data/fontmetrics/{style}.json; no code reads it

# FontForge environment (Python 3.11; system fontforge module symlinked in)
.venv-fontforge/bin/python run_print_implied_anchors.py
.venv-fontforge/bin/python run_print_implied_cap_marks.py
```

Two virtual environments exist because the system FontForge module is built for Python 3.11; see `README-VENV.md` for setup. Only scripts that `import fontforge` (the `implied_*` modules and their two wrappers) need `.venv-fontforge`.

`test_build_fontmetrics.sh` is not a test; it counts how often each semantic tag is true/false in the JSON dump. The tags are an early model of glyph properties for possible use in anchor candidates; no Python code reads them.

## Architecture

Python modules live in `src/libertinus_analysis/` (package `libertinus_analysis`); module names below are relative to it.

### Style keys and the font registry

Everything is keyed by style: `regular`, `italic`, `semibold`, `semibold_italic` (plus `*_patch` variants). `FONTS` in `font_context.py` maps each key to a font path and the **GPOS lookup index of its mark-to-base lookup, which differs per font** (4, 4, 1, 2). Anchor classes within that lookup are referred to by index: `0` = above, `2` = below (`1` above-right, `3` above-right/left-angle). In the fontmetrics these indices are string keys (`"0"`, `"2"`). **Original semibold differs:** its class `1` is the designer's `top_punkt`, a second above class (dot above U+0307, diaeresis, ring, hook above, comma above; base anchors 96 lower on lowercase, 83 on capitals, on only 24 bases), and its `3` and `4` are ogonek/hooks and cedilla. Stage 1 of the patch merges `top_punkt` into class 0; the fontmetrics, read from the original fonts, still have it.

### Data flow

1. **Extract** — `fontmetrics_extractor.py` reads the original fonts on demand and returns per-glyph bbox, anchors, width, sidebearings, tags (schema in `data/fontmetrics/SCHEMA.md`). Code gets this through `fontmetrics_loader.py` (`load_fontmetrics`, cached per run, read-only), so anything that needs outlines belongs in the extractor. The `data/fontmetrics/{style}.json` files are an optional dump from `run_build_fontmetrics.py`, for reading by eye; no code reads them, and they can be out of date.
2. **Derive** — `fontmetrics_helpers.py` holds the per-style reference tables (`VERTICAL_THRESHOLDS_OPT`, `ANCHOR_Y_REF_OPT`, `CLEARANCES_OPT`, `OPTICAL_CORRECTION`) and the candidate functions (`get_aya`, `get_bya`, and `get_anchor_candidate` for (X, Y)); see "Anchor model and candidates" below.
3. **Report** — `fontmetrics_report.py` builds LaTeX table bodies (one column per glyph, a block of rows per style) written to `tex/input/`, which `tex/libertinus-analysis.tex` `\input`s. The Latin and IPA base tables leave out letters whose anchors in the patched fonts are all inherited (stages 8 and 9) in every style; the patch records which anchors those stages set in `data/anchor_provenance/{style}.json` on every run, so run `run_patch_font.py` before `run_print_report_fontmetrics_full.py` after a patch change. The mark tables show each mark anchor in the original font (m), the patched font (mp) and the difference (mδ; semibold's class 1 is compared after its +96 raise); they no longer show a mark-anchor candidate. `combo_matrix.py` + `classifiers.py` produce the base x mark grids. Generated `.tex` fragments and the PDF are committed.
4. **Patch** — `font_patching.py` orchestrates stages on the GPOS lookup and GSUB (see below).

Character sets (which bases, which marks) come from `data/ipa/ipa_unicode.py` as `unicode_groups[NAME]["items"]`, e.g. `BASE_LATIN`, `BASE_IPA`, `MARK_ABOVE`, `MARK_BELOW`.

### Anchor model and candidates

**Read `ANCHOR-HEURISTICS.md` before calculating, auditing or patching any anchor.** It summarizes the model with every number and formula needed to compute a candidate: aspect bands, anchor Y references, clearances, overshoots, the per-style X formulas and K shifts, mark anchors, and which parts the code implements. The authority behind it is the report, `tex/libertinus-analysis.tex` ("Anchor model" through "Semibold italic anchor model", plus "Vertical aspects…"). When the understanding changes, update the report first, then `ANCHOR-HEURISTICS.md`. Keep the model in that file, not here.

In short: the base anchor is where the mark goes, so the clearance lives in the base anchor. Y is the glyph's vertical aspect plus that aspect's clearance, the same in every style. X is the bbox midpoint in roman. In italic it is the midline of the slanted advance-width lane at the anchor's own height. Semibold italic keeps the designer's model: the italic position minus a shift K (150 above, −12 below).

Standing rules:
- Candidates are geometric centres computable from metrics. They are not optical centres; a human curates where they fail.
- Designer anchors are inconsistent (wrong, copied between glyphs or styles, not snapped to references). Trust them only in aggregate, never as evidence of intent for a single glyph. The patch is meant to normalize them.
- **Never move semibold italic to the italic model** (decided 2026-10-12). Patch only anchors that do not conform to its own model.

### Patch pipeline (`font_patching.patch_font`)

Stages in order. Glyphs come first; scripted anchor stages (4–6) come before the human-curated anchors, which overrule them; derived letters (8) inherit after the curated anchors but never over one; precomposed inheritance is the last anchor stage; GSUB is rebuilt and the coverage sorted at the end.

Stages 8 and 9 are the two inheritance stages, with the same contract: each has its own list of letters (derived, precomposed) and sets an anchor only where the base letter fits inside the letter; the rest of its list is handled in earlier stages (curated in 7, a candidate in 6, or the designer's anchor). They stay separate because they differ in how the base is found (a hand-made list vs Unicode decomposition), in what they replace (stage 8 overrules designer and stage-6 anchors, stage 9 only fills gaps), and in stage 8's special cases (tails, stem midlines, `derived_y`); stage 9 also depends on stage 8 (Ǿ ǿ below inherit from Ø ø). What they share is in `font_patching_inherit.py`: `fit_base` and the interval fit behind it (also used by stage 8's `stem_shift`), outline sampling, and the base-record helpers that stages 5 and 6 use too (2026-11-11).

1. Clean up the lookup. First, `font_patching_mergeclasses.py` merges semibold's `top_punkt` (class 1) into class 0: its marks move to class 0 with anchor y + 96, its base anchors are dropped (G, which has no class-0 anchor, gets one from it), and U+0315 stays in class 1 as the above-right class of the other styles. Placement on lowercase is unchanged; the dot-like marks now attach wherever a class-0 anchor exists. It runs first so that stage 3 and later see one above class. Then delete bad anchors (`font_patching_deleteanchors.py`) so that stages 6–8 refill them. Anchors marked `"delete"` in `data/fontanchors_audit/overrides.py` are always deleted, for any reason, including not fitting the style's anchor model (semibold italic a, s, h, J above, which carried the slant; J below in every style, at the full-descender −319 on a letter that is not one). The audit's own "bad" verdicts are deleted only if `DELETE_BAD_ANCHORS` in `font_patching.py` is on; it is off because that list is unreviewed: about 490 deletions, about 150 of them outside stage 6's Latin/IPA scope and so left with no anchor, and in semibold italic it flags the copies of regular's anchors that the semibold italic model keeps. Prefer deletion + stage 6 over a curated anchor wherever the candidate is right; stage 7 is for anchors the candidate cannot get right. `anchor_audit.py` (run via `run_anchor_audit.py`) reads the original fonts, tests every above/below base anchor in the style's mark-to-base lookup whose glyph has a Unicode codepoint (unencoded small caps and alternates are ignored), and writes the bad and suspect ones with reasons to `data/fontanchors_audit/{style}.py`. Those files are regenerated on each run; human decisions go in `data/fontanchors_audit/overrides.py` (`"keep"` / `"delete"`). With the audit on, only "bad" anchors are deleted. Thresholds are constants at the top of `anchor_audit.py`. X is compared with K added back, so semibold italic is judged by its own model.

   The report's "Anchor audit" section, its review module (`anchor_review.py`) and the candidate fonts (`fonts/*-candidate.otf`) were removed on 2026-11-07, once every Latin and IPA above/below anchor had a decision; the decisions are the `"keep"`/`"delete"` overrides and the curated anchors. The precomposed test of `anchor_audit.py` ignores a below-mark tucked above the base's lowest point (the dot of ỵ).
2. Add glyphs and fix outlines — `font_patching_redraw.py` rebuilds semibold ɭ (U+026D) by control points as semibold l with its foot serif replaced by semibold ɖ's hook, as regular ɭ is built from regular l and ɖ (the designer's had a regular-weight stem; 2026-11-08); it checks the source control points and raises if they change. In every style it also rebuilds ʅ (U+0285, squat reversed esh) as ɿ's fishhook and stem with ɳ's retroflex hook (x-height top, hook to −221/−229; the designer's was 550 high in regular and a mirrored ʃ at the ascender elsewhere), and adds U+E27F `uni027F.desc`, ɿ with a descender (ɿ's top and q's descender serif; the SIL fonts' ɿ descends, Libertinus's baseline ɿ is kept) (2026-11-09). A floating mark (e.g. a floating tone) is NBSP + mark, so U+00A0 gets x-height above/below anchors in stage 7; the PUA spacing base U+E100 `space_en_base` that did this before was removed on 2026-11-09 (report, "Floating tones"). It also rebuilds italic ɍ (U+024D) from its own SplineSet in `fonts/LibertinusSerif-Italic.sfd`: the SFD glyph also refers to IJ and two acutes, so the compiled glyph was ɍ overlaid with ÍJ́ (advance 601); the rebuild drops the references, takes r's advance (357), and checks that the SFD's r, read the same way (contours reversed, as FontForge does for CFF), matches the compiled r (2026-11-11). Also U+034F `uni034F`, the combining grapheme joiner behind `\cgj`: empty, zero advance, GDEF class mark, as in Gentium Plus and Charis SIL. No positioning depends on it, since HarfBuzz hides CGJ with or without a glyph; it gives the font coverage and stops XeTeX's "Missing character" lines for each `\cgj`.
3. Add missing marks — `font_patching_addmarks.py` adds the combining marks a style lacks, with mark anchors, by copying outlines the designer drew elsewhere: semibold takes regular's outline (above marks moved right 12), semibold italic takes italic's outline moved right 12 with regular's anchor verbatim (the semibold italic anchor model), and `dotaccent.cap` in the two italic styles is the dot of the precomposed Idotaccent. `tildecomb.cap` (all styles, 2026-11-08, for Guarani G̃, which has no precomposed form) is the tilde of the precomposed capitals: `tildecomb` itself, except in semibold italic, where it is the taller tilde of Atilde. It opens the other original fonts to read those outlines. Copied above marks are made bolder to match the designer's own (about 12%): a part that is another mark is swapped for the style's own mark, and the rest is pushed outward by `embolden()`; below marks, lines and combining letters are copied unchanged. The "Adding missing marks" section of the report shows the emboldened ones. In semibold it also replaces U+0358–U+0363, which the original font fills with copies of the capital accents.
4. Capital-mark anchors and the mark-axis rule (`font_patching_markaxis.py`, see "Mark anchors" below) — `font_patching_capmarks.py` sets the mark anchor of each `.cap` accent from the precomposed capitals A–Z: y is the capital anchor reference (850) minus how far the mark is raised there (median); x is the outline's centre on its own axis for symmetric marks, and the median precomposed position relative to the base's midline for grave, acute, double acute, double grave; semibold italic subtracts K = 150. In regular, semibold and semibold italic every `.cap` anchor is scripted; curated ones are commented out (regular's grave and semibold italic's four asymmetric marks were removed 2026-11-08 in favour of stage 4, which matches the precomposed capitals). Italic's eight curated `.cap` anchors were refitted on 2026-11-07 so that each accent lands, as a median over the capitals, where the designer drew it in the precomposed glyphs (stage 4 left the symmetric ones about 14 left of them, the old curated caron about 15 right).
5. Normalize designer anchor y — `font_patching_normalizeanchors.py`. Every above or below anchor it sees is the designer's (bad ones are already deleted, and stages 6–7 run later). First, capitals with an above anchor in y 795–835 move to the capital reference, 850: the designer set semibold's near 805 and compensated only in the `.cap` marks, so marks without a `.cap` form crashed into capitals; a few capitals in the other styles had the same problem (Ŋ Ƅ Ƣ Ɋ Ћ Ỻ Ⱪ Ⱬ), so the rule applies in every style since 2026-11-08. Stage 4 adds the same 45 to the `.cap` mark anchors, stage 6 fills gaps from the same reference, and semibold's curated capitals are written at 850. Then any anchor within 5 of a reference for its class (`SNAP_TOLERANCE`; above: ascender, capital, x-height; below: baseline, descender) snaps to it. Anchors farther away are not moved; each prints as a `FAR` line with the audit's verdict. Most are legitimate (stacked marks on precomposed glyphs, superscripts, small caps at 685); the errors found among them were fixed on 2026-11-08 (report, after the anchor Y reference table).
6. Heuristic anchors — `font_patching_heuristicanchors.py` gives each base in `BASE_LATIN` ∪ `BASE_IPA` that lacks an above or below anchor its candidate from `get_anchor_candidate` (rounded), computed from the patched font's own bbox and advance (equal to the original fontmetrics except for glyphs redrawn in stage 2). It only fills gaps, never moves an existing anchor, and skips canonically decomposed glyphs (stage 8 handles them). Candidates fail where §4 of `ANCHOR-HEURISTICS.md` says (e.g. j's above X, pulled left of the stem by its hook); curated anchors in stage 7 overrule them.
7. Human-curated anchors from `data/fontanchors_human/{style}.py` (`bases`, `marks`, `bases_by_name`, `marks_by_name`; overwrite or create, never delete). A curated anchor that a scripted stage (or the designer's own anchor) reproduces within about 10 units is redundant and is commented out with a note naming what reproduces it (audit of 2026-10-29); keep curated anchors for what the stages cannot get right. Then stage 7b, the stem-axis rule (`font_patching_stemaxis.py`, 2026-11-12): letters with a central stem and no curl, the basest ones only (`CENTRAL_STEM`: i ı j ȷ l m I T ɪ, above and below, j ȷ above only; m by its middle stem, `CENTRAL`; never derived letters, which stage 8 moves with their base; not ɾ ɿ), get their anchor X on the stem's axis, over designer and curated anchors alike (each curated X it changes is reported; the curated ones are written at its X). The stem is the pair of straight edges from the control points (`stem_line` in `font_patching_inherit.py`); its midline is taken at the top (above) or bottom (below) of the straight part and carried to the anchor at the declared slant (`ANGLE`; the stem's own angle was rejected), less K; Y is not touched. In the italic styles curls move the optical centre: dotted i and j take the centre of the dot (`DOT_CENTRED`), ı and ȷ the axis of that dot (`DOT_AXIS_OF`), and the below anchors of i ı l (`CURL_FOOT`) and m above (`CURL_ABOVE`) are left out, to be curated (the report's to-do item "Recheck all curated anchors A–Z and a–z in all styles"). `regular` is far more complete than the other styles.
8. Derived letters — `font_patching_derivedanchors.py` gives each letter listed in `data/derived_letters.py` (a base letter plus a bar, stroke, hook, tail, curl or belt; classes per entry, optionally per style) its base letter's final anchor moved by the fit of the base inside the derived letter: `fit_base` (in `font_patching_inherit.py`, shared with stage 9; since 2026-11-11), per class, on the inherited side only, a shift plus a scale of up to 15%, evaluated at the mark's axis, so a letter drawn a few percent wider (the italic capitals with a hook or bar) keeps the anchor at the same place in the shape. It inherits a class only where the fit is at least 80% (`MIN_FIT`), and never over a curated anchor. Letters in `stem_axis` (ƚ ɫ ɬ ⱡ Ɫ ɩ ɟ: a bar, belt or tilde across an l, ı or ȷ stem) take the shift between the two stems' midlines (`stem_midline`) whatever the fit. Before 2026-11-11 the whole outline was matched by translation only (`outline_shift`, still used for the X shift of `derived_y`). The derived letters are also in `BASE_LATIN` / `BASE_IPA`, so that stage 6 fills what stage 8 cannot (a style where the letter was redrawn); the stroke and bar letters added 2026-11-11 (Ŀ ŀ Ŧ ŧ Ǥ ǥ Ƚ ƚ Ⱥ ⱥ … ʡ ʢ) are there and, for capitals, in `@capitals`. It runs after stage 7 so that it inherits the base's final anchor. A letter in `derived_y` (ɕ below, ɼ above) has that anchor's Y set by hand in that file, and takes X from the base letter's final anchor plus the shift, whatever the match. Letters in `bottom_tail` (a hook, tail or curl at the bottom: Ƒ Ɲ ɖ ɭ ɱ ɲ ɳ ɽ ʂ ʈ ʐ …) are matched on the stems above the tail instead (`stem_shift`), and their below anchor takes the candidate's Y (descender) where the tail has ink within 195 of the mark's axis, else the base letter's Y; with a stem match under 70% the above anchor is skipped and a below anchor over a tail gets the full candidate. `run_derived_anchor_report.py` writes the comparison sheet `tex/input/derived_anchors.tex` (designer, candidate, inherited, curated, per style) and the stem-midline check of the l-like and i-like letters `tex/input/stem_check.tex`, and `run_print_combo_matrix.py` the grids `tex/input/derived_inherit_{above,below}.tex` (groups `DERIVED_ABOVE` / `DERIVED_BELOW` in `ipa_unicode.py`, each base letter followed by its derived letters); both are in the "Derived letters" section of the report, just before "Precomposed characters", with a short "Turned letters" subsection (their anchors are candidates or curated, never inherited).
9. Precomposed inheritance — `font_patching_precomposed_anchors.py` gives each precomposed Latin letter listed in `data/precomposed_letters.py` (`PRECOMPOSED_ABOVE`, `PRECOMPOSED_BELOW`; Latin-1 Supplement through Latin Extended Additional, generated and then reviewed 2026-11-07) that lacks the anchor its base letter's final anchor, moved by the fit of the base inside the precomposed glyph: ink intervals on the inherited side only, shift plus a scale of up to 15%, at least 80% (`fit_base`). The base is the deepest Unicode decomposition base, or ı / ȷ for i / j below. Semibold italic builds most precomposed glyphs with the base 12 right, and many italic capitals with an accent above are about 5% wider, so the fit matters. A letter inherits above only if it has no above mark, below only if it has no below or attached-below mark (except ģ, whose cedilla U+0327 is drawn as a comma above; added to `PRECOMPOSED_BELOW` by hand, 2026-11-10); `EXCLUDED_ABOVE` / `EXCLUDED_BELOW` leave out letters per style with a reason (ģ, horn letters above, weak fits). Every weak fit (semibold ą above; italic and semibold italic Ĵ, semibold italic ư ứ ừ ử ữ below) has a curated anchor in stage 7 instead, listed in the report's "Precomposed characters" section. Existing anchors are reported and never replaced. `BASE_ABOVE` / `BASE_BELOW` in `ipa_unicode.py` are now only the test sheets' base lists.
10. GSUB `ccmp` rebuilt from `data/fea/{style}/ccmp.fea` (dot removal, `.cap` accent forms). `@capitals` lists the capitals after which above marks take their `.cap` form; besides A–Z, Æ Œ and the IPA/African capitals, it has every capital of stage 9's `PRECOMPOSED_ABOVE` (2026-11-08), and `BASE_CAP` in `ipa_unicode.py` mirrors its Latin and IPA entries for the capital alternates grids. feaLib's builder destroys GPOS and GDEF, so both are saved and restored around the build.
11. Sort coverage — `font_patching_sortcoverage.py` sorts the mark-to-base lookup's BaseCoverage and MarkCoverage by glyph ID, with their records, because the anchor stages append glyphs at the end (otherwise fontTools warns "Coverage is not sorted by glyph ids" on every compile).

### Mark anchors

The mark anchors have been reviewed style by style by hand (against regular, the precomposed glyphs and the mark zone figures); there is no scripted audit of them, and the only scripted mark-anchor stages are the `.cap` forms (stage 4) and the mark-axis rule (decided 2026-11-09, `font_patching_markaxis.py`, run in stage 4): a symmetric above mark in `SYMMETRIC_ABOVE` (every mirror-symmetric above mark, and the combining Latin letters U+0363–036F; not the grave, acute, double acute, double grave, hook, commas, half rings or arrowhead), and since 2026-11-12 each mirror-symmetric below mark in `SYMMETRIC_BELOW` (not the tacks, which are decided, nor grave/acute below, half rings, comma below, left angle below; K below is −12 in semibold italic, `SHIFT_K_BELOW`), gets its anchor X on its own axis (`k = K` exactly; 0, or 150 in semibold italic; no threshold since 2026-11-12, it was `|k − K| ≥ 10`). k is measured on the centre of the mark's de-slanted ink bounds (the mirror or 180°-rotation symmetry axis is within 2.2 units of it on every mark, so it was kept, 2026-11-12; test sheet `tex/mark_symmetry_axis_test_sheet.pdf`), except where `AXIS_MEASURE` says otherwise: the area centroid for the combining letters that are not boxy (e c h r t), the stem for combining i. For symmetric marks the model, not the precomposed glyphs, decides X: a per-mark fit to the precomposed glyphs would carry the base anchors' offset into every mark. Y is not touched. The mark-snap test (`run_mark_snap_sheet.py`) moved every mark anchor onto the model (`X = C + Y tan θ + d − K`, `ANCHOR-HEURISTICS.md` §3) and was rejected: most moves were under 20 units, and as many marks got further from the precomposed glyphs as got closer. HarfBuzz substitutes the precomposed glyphs wherever they exist (authors are not expected to use CGJ), so a composed combination should match them; that is the criterion for everything except the X of symmetric marks under the mark-axis rule. Vertical evidence: the median Δy of a mark (composed minus precomposed, on x-height bases, where it is usually the same on every base) is evidence for moving its anchor Y.

- Mark anchors change one at a time, as curated anchors in the `marks` / `marks_by_name` dicts of `data/fontanchors_human/{style}.py`, where the precomposed glyphs support the change. Check them by eye against the mark zone figures (`run_print_mark_zones.py`).
- A curated mark anchor is the final anchor, set in one place: it must obey the mark-axis rule itself (stage 4 skips curated marks and reports any that do not). A vertical move in an italic style moves X by Δy·tan θ too, so that the mark keeps its k.
- The report's "Mark anchor model" section is a short overview of what the patch changes; the detail (evidence, figures, dates, test sheets, rejected alternatives) is in `MARK-ANCHOR-HISTORY.md`. Record new findings there, and change the report only when what the patch does changes.
- The Δy moves of 2026-11-09 (`MARK-ANCHOR-HISTORY.md`, "Vertical moves from the precomposed glyphs") are curated: dot above in all four styles, macron in all but italic (whose precomposed glyphs disagree), semibold tilde, semibold italic ring, and the double acute. The mark-zone consistency moves of 2026-11-12 (`MARK-ANCHOR-HISTORY.md`, "Mark-zone consistency across styles") supersede them for the dot above and the semibold italic ring, and add dot below and diaeresis below (all styles), semibold diaeresis and `dieresis.cap`, semibold breve below: where the designer's precomposed letters disagree between styles, a mark sits at the same place in its style's mark zone in every style instead (test sheet `tex/mark_zone_consistency_sheet.pdf`). Open decisions go in the "Open decisions" paragraph of the report's "Mark anchor model" section (after Figure 4); when decided, move them out, with a one-line summary under "Decided: left as they are" or "What the patch changes" in the report and the detail in `MARK-ANCHOR-HISTORY.md`.
- Capital forms (`grave.cap`, `acute.cap`, …) are set by stage 4 from the precomposed capitals. Only italic has curated ones (eight); in the other styles all are scripted.

Files with `legacy` in the name (`font_patching_legacy.py`, `font_patching_helpers_legacy.py`, `legacy-geometry.py`, `data/legacy-fontdata/`) are superseded and not on the active paths. `data/vertical_data.py` predates the `*_OPT` tables in `fontmetrics_helpers.py` and disagrees with them in places; the `*_OPT` tables are the ones the code uses.

## LaTeX conventions

From `README-FONTS.md`: fonts are loaded with `fontspec` from `fonts/`; always use `Path = ../fonts/` and always include the file extension (`.otf`, `.ttf`). Semibold is the bold face. The patched family is `\LibertinusSerifPatch`. Table cells render sample glyphs as `\char"XXXX`, with `\cgj` between base and mark in the fontmetrics tables.
